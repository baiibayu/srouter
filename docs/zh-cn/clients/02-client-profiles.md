## 什么是配置文件

一个客户端配置文件 = 一把**按客户端发放的 API 密钥**（`sk-cp-…`）+ 一段可选的
**系统提示词（由服务器始终应用）**。在仪表盘的 **密钥 → 客户端配置文件** 中管理。

它的存在有两个理由：

1. **每个下游客户端一把独立凭据。** 轮换或停用其中一个客户端的密钥，完全不影响
   其他客户端。
2. **网关强制的指令。** 只要使用该密钥发起请求，配置文件的提示词就会在服务器端
   注入——无论调用方发送什么，都无法删除或覆盖它。

配置文件密钥并不是统一密钥的"更好版本"或"备用密钥"。两者是通往同一个路由器的
平行凭据：相同的路由策略、相同的回退链、相同的提供方资源池。

## 两种推理凭据

| | 统一密钥（`sr-…`） | 配置文件密钥（`sk-cp-…`） |
| --- | --- | --- |
| `/v1` 推理 API | 可以 | 可以（见[端点支持](#端点支持)） |
| 仪表盘 `/api` | 不可以——需要会话登录 | 不可以 |
| 注入系统提示词 | 从不 | 配置后会注入 |
| 独立的预算 / 限额 / 分析 | — | 没有——流量保持聚合统计 |

## 创建配置文件

1. 打开 **密钥 → 客户端配置文件**，点击**创建配置文件**。
2. 填写名称，以及可选的系统提示词（最多 32 000 字符）。
3. **立即复制**生成的 `sk-cp-…` 密钥——它只会显示一次
   （"请立即复制此密钥——之后将不再显示"）。

服务器为凭据保存两份数据：SHA-256 哈希（认证时唯一使用的数据），以及一份
AES-256-GCM 密文（仅用于在仪表盘渲染掩码形式的密钥）。认证用途绝不存储明文。

## 服务器强制的系统提示词

当携带配置文件密钥的请求到达、且该配置文件设置了提示词时，服务器会将其作为
**第一条**系统消息前置到调用方自己的系统消息之前：

```jsonc
// 客户端发送的：                  // 上游模型实际收到的：
[
  { "role": "system",                [
    "客户端自己的指令"         →       { "role": "system", "content": "配置文件提示词（第一条）" },
  ],                                  { "role": "system", "content": "客户端自己的指令" },
  { "role": "user", "content":       { "role": "user", "content": "你好" }
    "你好" }                         ]
}
```

调用方的指令会保留在强制提示词**之后**：客户端可以补充上下文，但不能覆盖或删除
配置文件的规则。提示词为空或未设置时为中性直通——密钥正常认证，不注入任何内容。
统一密钥则永远不注入任何内容。

注入发生在携带 messages 的端点上：
`/v1/chat/completions`、`/v1/completions` 和 `/v1/responses`。

## 端点支持

配置文件密钥认证的是在 `server/src/app.ts` 中挂载的 OpenAI 兼容 `/v1` 接口：

| 端点 | 配置文件密钥 |
| --- | --- |
| `POST /v1/chat/completions` | 可以 — 注入提示词 |
| `POST /v1/completions` | 可以 — 注入提示词 |
| `POST /v1/responses` | 可以 — 注入提示词 |
| `GET /v1/models` | 可以 |
| `POST /v1/embeddings` | 可以 |
| `POST /v1/images/generations`、`/v1/videos/generations` | 可以 |
| `POST /v1/audio/speech`、`/v1/audio/transcriptions` | 可以 |
| Anthropic `POST /v1/messages` | **不可以** — 仅统一密钥 |
| 原生 Gemini API | **不可以** — 仅统一密钥 |
| Ollama 模拟接口 | **不可以** — 仅统一密钥 |
| MCP 服务器 | **不可以** — 仅统一密钥 |
| 仪表盘 `/api/*` | **不可以** — 仅会话登录 |

换句话说：讲 OpenAI 方言的智能体可以用自己的配置文件密钥；指向 Anthropic、
Gemini、Ollama 或 MCP 接口的客户端继续使用统一密钥。

## 安全边界

- 查找是时序安全的：统一密钥通过基于 HMAC 的常量时间比较，配置文件密钥通过带索引
  的 SHA-256 摘要解析，两者都不会泄露长度或逐字节时序。
- **已停用**的配置文件与未知密钥被完全一样地拒绝（相同的
  `401 Invalid API key`），因此被吊销的客户端无法分辨"已停用"与"已删除"。
- 配置文件密钥在仪表盘 `/api` 路由上**永远无效**——那些路由由仪表盘会话把关，
  而非任何推理凭据（统一密钥同样打不开）。

## 配置文件不做什么

请保持合理预期——配置文件是凭据与提示词功能，不是调度或计费功能：

- **没有独立预算。** 每月请求/令牌上限挂在*提供方密钥*上，由所有下游流量共享——
  它们"不单独适用于下游客户端配置文件"
  （[预算文档（英文）](../../en/api/01-rest-api.md#monthly-provider-key-budgets)）。
- **没有排队、优先级或轮流机制。** 所有请求（统一密钥或配置文件）都并发经过同一个
  路由器；配置文件既不会串行化流量，也不会隔离流量。
- **没有按配置文件的分析。** 仪表盘上的用量对所有凭据聚合统计。
- **不是客户端之间的防崩溃机制。** 两个智能体操作同一批文件时的协调是智能体自己的
  事，与网关无关。

## 轮换、停用与编辑

| 操作 | 效果 |
| --- | --- |
| **轮换密钥** | 签发新的 `sk-cp-…`，旧密钥立即失效（泄露后使用）。 |
| **启用开关关闭** | 密钥以标准 401 拒绝；其他配置文件不受影响。 |
| **编辑提示词** | 下一个请求生效；清空后密钥仍有效但停止注入。 |
| **删除** | 配置文件与哈希一并删除，该密钥永远无法再认证。 |

## 示例

```bash
curl http://localhost:20268/v1/chat/completions \
  -H "Authorization: Bearer sk-cp-..." \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello"}]}'
```

两个智能体并行运行的常见配置：为每个智能体创建一个配置文件，各自带上强制提示词
（例如不同的输出语言或详细程度），把各自的密钥放进对应智能体的配置里。轮换或停用
其中一个智能体的配置文件，绝不影响另一个。
